# lead picks the final arms from the probe numbers (python -m nca.strand.probe). Each cell sees only static board facts
# and, on the tapped cell only, the rule's 53-bit code + the tapped chord's two edges (no owner slot: M1 is one player).
# Arms (each its own process on the one L4; channels 96, hidden 128, depth 1 unless named):
#   v6a    A  type one-hot + rotation one-hot + mirror (16 static planes)
#   v6c    C  per-direction edge classes + anchor + mirror (55)
#   v6d    D  type one-hot + rot / 6 as one number + mirror (11)
#   v6big  C at channels 128, hidden 256, depth 2, batch 16 (2.65x the FLOPs of an arm above per cell-step; 2.5x the
#          CPU time per iteration on the Pi) -- C because the probe ranks C over A at width 128 and A only catches up at 1024
#   optional, commented out: v6cbc (C with the code broadcast to every cell: the diagnostic ceiling) and v6e (option E,
#   local-frame perception, nets.FrameNCA: the probe's E-local learns the lookup fastest; parity-tested equivariant)
# Stages per arm (the doc's chain, --init from the previous stage's best.pt; later stages at lr 2e-4, not 5e-4):
#   l2   M1a on level-2 patches                            25 min
#   l3   M1a on levels 2 + 3                              240 min
#   l4   M1a on level 3 + level-4 crops                   150 min
#   m1b  M1b with the tap held (12 planes) on 2 + 3 + 4    60 min
# = 475 min a run + SETUP_MIN 25 = 500 min = ~8.3 VM-hours (MAX_HOURS 12), ~$3.4 at ~$0.41/h, whatever the number of
# arms (they share the GPU). The VM adds --schedule time (lr steps at 60% / 85% of each stage's minutes).
# Throughput (estimated, not measured on the L4): an arm above is ~3.2x the per-cell-step FLOPs of plan 5's m128 (96
# channels and 76-115 consts vs 32 and 22), big ~10x; four arms sharing the GPU get roughly 2 s / iteration each (big
# ~6 s) against plan 5's 0.36 -- an l3 stage is then ~7k iterations an arm (big ~2.4k), not ~25k. Fewer arms, or
# --batch 16, buy iterations back.
# GPU memory (estimated: the backprop window keeps ~(state + consts + hidden) floats per cell for each of the 48 steps):
# ~4.7 GB an arm above at batch 32 on level-4 crops, big ~9.5 GB at batch 32 -- hence big at --batch 16 (~4.8 GB), so
# the four fit the L4's 24 GB (~19 GB + contexts). A fifth arm (v6cbc ~5 GB, v6e ~4.6 GB) needs one dropped or batch 16.
